Quick Trigger Reference

Read the phrase → pick the service · no second guessing

Shared Responsibility — Service by Service

"Who patches the Amazon RDS database engine?"→AWS
"Who manages security groups on Amazon RDS?"→Customer
"Who manages code in AWS Lambda?"→Customer
"Who patches the Lambda runtime and OS?"→AWS
"Who is responsible for the physical data center?"→AWS — always
"Who configures AWS IAM permissions?"→Customer — always
"Customer ALWAYS owns, every service"→Customer data
"Shared control — both AWS and customer"→Patch mgmt · Config mgmt · Training
"Who patches guest OS on Amazon EC2?"→Customer
"Who maintains the hypervisor under Amazon EC2?"→AWS

Well-Architected Framework — 6 Pillars · OSRPCS

"Operations as code" · "Frequent, small, reversible changes" · "Anticipate failure"→Operational Excellence
"Protect data and systems" · "Least privilege" · "Encryption"→Security
"Recover from disruption" · "Dynamically acquire resources" · "Automatically recover"→Reliability
"Right instance type" · "Use resources efficiently" · "Adapt as tech evolves"→Performance Efficiency
"Avoid unnecessary costs" · "Right-sized resources" · "Match supply to demand"→Cost Optimization
"Minimize environmental impact"→Sustainability
NOT a pillar — exam distractors→"Resilience" · "Confidentiality" · "Availability" · "Agility"

AWS IAM — Users, Groups, Roles, Policies

"One specific person · long-term credentials · named individual"→IAM User
"Share permissions for many users at once · all devs should have"→IAM Group
"Service needs access · temporary credentials · no long-term keys"→IAM Role
"JSON document · Allow/Deny · defined permissions"→IAM Policy
"Account owner · lock with MFA · do not use daily · first time setup"→Root User
"EC2 needs to access Amazon S3"→IAM Role (never hardcode keys)
"Groups can be nested inside other groups"→FALSE — groups cannot be nested
"IAM is regional — set up per Region"→FALSE — IAM is global
